## Source and local evidence

The repository patch is [hyprland-subsurface-parent-lifetime.patch](../overlays/temporary/patches/hyprland-subsurface-parent-lifetime.patch). It adds a `surf` check to `posRelativeToParent()` and `t1Parent()`. The [local incident note](hyprland-subsurface-crash.md) records a parent-first teardown crash on revision `ee0409623e2d6a683374b39a32e0ac3d087841aa` and a successful patched reproduction. Those runtime results are prior evidence, not tests rerun in this research task.

Upstream `main` resolved through GitHub's REST API to [34eb03bd8da01024596c367fba66485a8c9b8ca7](https://github.com/hyprwm/Hyprland/commit/34eb03bd8da01024596c367fba66485a8c9b8ca7), committed September 6, 2026 at 11:00:56 UTC. [Subcompositor.cpp at that revision](https://github.com/hyprwm/Hyprland/blob/34eb03bd8da01024596c367fba66485a8c9b8ca7/src/protocols/core/Subcompositor.cpp#L131) still dereferences both weak-parent locks without a null check.

Two related concerns remain in that source:

- Both loops advance `surf` but obtain each next subsurface role from the original `m_parent`. With three subsurface levels, they repeat one ancestor's offset or stop at an intermediate ancestor. This predates the local patch.
- A null return from `t1Parent()` needs caller review. In [getPreferredImageDescription()](https://github.com/hyprwm/Hyprland/blob/34eb03bd8da01024596c367fba66485a8c9b8ca7/src/protocols/core/Compositor.cpp#L712), upstream dereferences the returned parent without checking it. This is a source-level incomplete-lifetime-handling concern, not a newly reproduced second crash. The synchronized-commit caller in the same file already checks the returned parent.

The color-description concern has a concrete protocol entry point. [ColorManagement.cpp](https://github.com/hyprwm/Hyprland/blob/34eb03bd8da01024596c367fba66485a8c9b8ca7/src/protocols/ColorManagement.cpp#L399) checks only whether the feedback object's own child surface is expired before handling `get_preferred` or `get_preferred_parametric`. Keeping that surface and its subsurface resource alive, destroying the parent surface, and requesting preferred feedback can pass that check while `t1Parent()` returns null. The forced-HDR early return must be disabled when testing this path. This sequence needs runtime confirmation and a regression test; the existing teardown client does not bind color management.

The [Wayland specification](https://wayland.freedesktop.org/docs/html/apa.html#protocol-spec-wl_subsurface) explicitly describes unmapping a subsurface when its parent `wl_surface` is destroyed. Parent-first destruction is therefore a protocol lifecycle the compositor must handle. The specification also forbids choosing a descendant as a new parent; the old source comment suggesting cycles might be permitted is not sufficient justification for changing protocol behavior.

## Recommended implementation scope and evidence

Prepare one local candidate focused on subsurface ancestor lifetime and traversal, acknowledging #15446 as prior work. Add the parent checks and any directly necessary caller handling; demonstrate deeper ancestry behavior with a separate test before including a traversal correction. Keep unrelated synchronization, rendering, and protocol cleanups out. Do not blindly copy #15446's stale-role protocol error decision without checking whether the state is reachable and what the protocol requires.

A preexisting checkout at `~/Developer/upstream/Hyprland` already contains uncommitted edits to `Subcompositor.cpp`, the surface-scale-transform client and test, and the hyprtester plugin. This research did not alter them. A future session must inspect and preserve that work before deciding whether to reuse it in an isolated checkout. Do not reset or overwrite it.

The existing [Wayland client](../tests/hyprland/subsurface-parent-teardown.c) waits for a child frame callback before destroying an intermediate parent surface. The [runner](../tests/hyprland/check-subsurface-teardown.sh) isolates its compositor, runtime directory, activation environment, and output backend; it checks both parent-first destruction and client disconnect cleanup. Preserve that mapped-state prerequisite and post-disconnect compositor health check. Zero positions and only two subsurface levels do not detect the deeper ancestry defect.

For upstream inclusion, adapt this behavior to `hyprtester`, using its generated C++ Wayland bindings and client registration rather than adding a standalone Nix-specific runner. [hyprtester/CMakeLists.txt](https://github.com/hyprwm/Hyprland/blob/34eb03bd8da01024596c367fba66485a8c9b8ca7/hyprtester/CMakeLists.txt) already builds Wayland clients using `clientNew`; its existing [child-window client test](https://github.com/hyprwm/Hyprland/blob/34eb03bd8da01024596c367fba66485a8c9b8ca7/hyprtester/src/tests/clients/child-window.cpp) illustrates process and socket integration, though it tests xdg child windows rather than this protocol. Test ordinary child-first destruction too. Exercise a live child after losing an immediate or higher ancestor, and add distinct nonzero offsets on a longer chain if correcting traversal.

The [upstream test guide](https://github.com/hyprwm/hyprland-wiki/blob/67c2562e2f0b0a6e61a81bcfcff6547312441d64/content/contributing-and-debugging/tests.md) requires new tests in GoogleTest or hyprtester. Debug builds enable tests. The documented commands include `ctest -j$(nproc) -C Debug --test-dir=build` and `make test`; targeted integration tests use `make TESTS="testName" test`. Run the mapped teardown regression against unpatched and patched builds and retain exact revisions and logs. A future session should provide the local diff and factual test evidence to the human without composing a PR body.
