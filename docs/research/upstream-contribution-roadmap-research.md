# Upstream contribution and retirement roadmap

> Historical roadmap: later package retirement supersedes its recommendations to retain the personal Codex and ChatGPT channels. Current consumers select official Nixpkgs applications.

Reviewed: 2026-10-16. Scope: **38 registered temporary fixes, 84 personal recipe directories and 106 patch artifacts**: 24 under root overlays and 82 under personal recipes. The matrices distinguish software bugs, missing packaging, optional product features and deliberate distribution policy. Counts describe this source snapshot, not the number of PRs required.

## Answer

Some changes warrant new upstream contributions, but the largest immediate opportunity is finishing existing work and adopting fixes already accepted upstream. Submitting every local overlay or patch unchanged would duplicate open proposals, combine independent bugs, or ask projects to adopt distribution-specific policy.

The recommended order is:

1. Finish narrowly blocked existing proposals: formatting, rereview, dependency readiness and rebases.
2. Prepare small portable bugfix PRs with a failing reproduction against current upstream.
3. Follow accepted fixes through releases, dependency updates and selected pins.
4. Seek maintainer agreement before proposing broader UI, authentication, library ownership or font-discovery designs.
5. Retain deliberate variants, including independent Codex/ChatGPT latest channels, while upstreaming reusable builder improvements separately.

The complete evidence and item-by-item removal conditions are in the [38-fix root matrix](upstream-root-fixes-research.md), [69 non-Craft recipes and 35 patches](upstream-personal-packages-research.md), and [15 Craft recipes and 47 patches](upstream-craft-packages-research.md). The personal matrix also indexes all 84 local recipes. These inventories include scripts/substitutions relevant to a recipe; having no `.patch` file does not establish equivalence.

“When” is therefore an event chain: **acceptance → containing source/release → dependency/recipe adoption → selected pin → unpatched regression/native acceptance**. Direct flake inputs can skip a Nixpkgs release; nested SDKs and independently pinned definitions add steps. No reliable maintainer deadline was established. A release PR, generated changelog date, successful CI job or closed issue is insufficient to promise a retirement date.

## Personal recipes: consolidation and deliberate exceptions

BookOrbit's stock3.4 packaging is a promising whole-recipe consolidation candidate after runtime/migration/sandbox comparison. Existing stock LibreOffice, Teams and `t3code` attributes should be improved rather than proposing duplicate package names. Existing REA, Claude Desktop, Soularr, Steam, LinearMouse and Vorssaint submissions have concrete scope/platform differences recorded in the matrix.

WordCraft/SoundCraft initializations are merged but not present at the selected older root pin; current upstream recipes are0.6.1 while personal recipes are0.7.0. Version, Darwin bundle integration, test coverage and font inputs still differ. FigCraft and Craft Launcher are legitimate new Nixpkgs recipe candidates after another naming/ownership check.

Curated fonts, downstream branding, optional emoji substitution, user/runtime asset acquisition and host integration are not automatically upstream bugs. Prefer optional supported inputs/configuration where maintainers agree; preserve distribution notices and actual behavior. Apple emoji's earlier request was rejected on distribution grounds, while PSScriptAnalyzer's request closure was administrative and explicitly left room for a maintained PR. These need different actions.

**Keep `codex-latest` and `chatgpt-latest` as independent latest channels**, even during stock version parity. Upstream packaging, helper integrity, native runtime and updater improvements can reduce their implementation burden without removing those exports or forcing platform feeds to lag together.

## Validation and limits

This research inspected current recipes/patches, immutable source comparisons, known PRs and relevant issue/comment/review/discussion evidence. Search coverage and pagination limits are recorded in each matrix. Negative searches mean no matching proposal was found within that coverage. They do not establish that no unpublished, differently worded or external effort exists.

The initial research created no upstream issues, comments or PRs and did not implement or validate proposed patches. The explicitly marked implementation follow-up records later work. Historical tests and concurrent local package acceptance remain distinct from testing an unmodified containing release. Documentation checks and independent evidence review apply to this report; package removal requires the item-specific gates above.
