# uBlock Origin configuration research

Reviewed: 2026-10-01. Scope: full uBlock Origin in Firefox and Zen, and Helium's bundled Chromium extension. This note supports a browser policy that protects privacy and blocks malicious and unwanted content while keeping ordinary sites usable without a maintained list of site exceptions.

## Answer

Use uBlock Origin's default easy blocking mode with its maintained core lists, automatic list updates, cosmetic filtering, and the normal popup and dashboard controls. Keep advanced user mode and global dynamic rules off. Firefox and Zen should retain the default startup wait for loaded lists and CNAME uncloaking. Helium needs its own bundled extension and browser-specific assets checked at runtime; Firefox-only CNAME and startup guarantees cannot be asserted for it. These choices keep the full uBO filtering engine and user controls available without a standing rule set that requires per-site repairs. [uBO's easy-mode guide](https://github.com/gorhill/uBlock/wiki/Blocking-mode:-easy-mode), [filter-list guide](https://github.com/gorhill/uBlock/wiki/Dashboard:-Filter-lists), and [Firefox comparison](https://github.com/gorhill/uBlock/wiki/uBlock-Origin-works-best-on-Firefox) support this balance.

## Findings and sources

### Policy format and settings

The [managed-storage schema](https://github.com/gorhill/uBlock/blob/master/platform/common/managed_storage.json) defines `userSettings` and `advancedSettings` as arrays of `[name, value]` **string** pairs; `adminSettings` is a JSON string in uBO backup format; and `toOverwrite.filterLists`, `toOverwrite.filters`, and `toOverwrite.trustedSiteDirectives` are string arrays. The [deployment guide](https://github.com/gorhill/uBlock/wiki/Deploying-uBlock-Origin:-configuration) says valid user-setting pairs overwrite their respective defaults at launch. A browser accepting a policy establishes only syntax acceptance, so inspect the extension dashboard after launch to verify consumption.

| Setting or control | Recommendation | Basis |
| --- | --- | --- |
| `autoUpdate` | `true`, or leave at its default | Periodic updates are the [recommended default](https://github.com/gorhill/uBlock/wiki/Dashboard:-Filter-lists). |
| `prefetchingDisabled` | `true` | Prefetching can establish connections before filtering. [Chromium may ignore this control for page-triggered DNS and preconnections](https://github.com/gorhill/uBlock/wiki/Dashboard:-Settings). |
| `hyperlinkAuditingDisabled` | `true` | Prevents hyperlink auditing pings, per [uBO's settings guide](https://github.com/gorhill/uBlock/wiki/Dashboard:-Settings). |
| `cnameUncloakEnabled` | `true` on Gecko; omit on Chromium | [uBO documents CNAME uncloaking as Firefox-only](https://github.com/gorhill/uBlock/wiki/Dashboard:-Settings). The setting is enabled by default on supported platforms. |
| `advancedUserEnabled`, `dynamicFilteringEnabled` | `false` or leave the stock mode | [Advanced mode enables dynamic filtering and can reduce protection when misunderstood](https://github.com/gorhill/uBlock/wiki/Advanced-user-features). The user's prior site rules should not be restored. |
| `suspendUntilListsAreLoaded` | `true` on Gecko; leave Helium's default | [Firefox enables startup suspension by default; Chromium disables it because it cannot suspend requests natively and enabling it can have side effects](https://github.com/gorhill/uBlock/wiki/Dashboard:-Filter-lists). Explicit `true` on Gecko guards against a retained contrary profile value. |
| `filterAuthorMode`, `updateAssetBypassBrowserCache`, `disableWebAssembly` | Leave default | These are [development or advanced controls](https://github.com/gorhill/uBlock/wiki/Advanced-settings), without a daily-use benefit here. |

Keep the dashboard, popup, logger, element picker, and per-site controls accessible. They are the built-in tools for diagnosing occasional filter breakage; the policy schema allows disabling the dashboard or popup parts, but doing so offers no stated protection benefit. [uBO dashboard guide](https://github.com/gorhill/uBlock/wiki/Dashboard), [managed-storage schema](https://github.com/gorhill/uBlock/blob/master/platform/common/managed_storage.json).

### Filter lists and performance

The [upstream asset registry](https://github.com/gorhill/uBlock/blob/master/assets/assets.json), inspected on 2026-10-01, marks the following nonregional filter lists on by default: `ublock-filters`, `ublock-badware`, `ublock-privacy`, `ublock-unbreak`, **`ublock-quick-fixes`**, `easylist`, `easyprivacy`, `urlhaus-1`, and `plowe-0`. `user-filters` is uBO's local user-filter list, included in the [deployment guide's default-selection example](https://github.com/gorhill/uBlock/wiki/Deploying-uBlock-Origin:-configuration). The registry has **no `ublock-abuse` entry**. The repository's [Gecko uBO list](../../modules/home/browsers/shared/ublock.nix) and [Helium uBO list](../../modules/shared/chromium-policies.nix) now select Quick fixes in place of the obsolete key. The registry observation does not establish that every packaged browser has already updated to the same asset revision.

The [Helium fork's registry](https://github.com/imputnet/uBlock/blob/main/assets/assets.json), inspected on the same date, has the same Quick fixes replacement and additionally defines `helium-annoyances` and `helium-unbreak`. It also enables several general annoyance and supplementary lists by default. Helium's [build patch](https://github.com/imputnet/helium/blob/main/patches/helium/core/ublock-setup-sources.patch) bundles its own assets and removes remote URLs from that bundled registry. A managed `filterLists` overwrite should therefore use keys present in the **installed Helium asset registry**. The two Helium-specific lists address browser-specific behavior, but selecting the entire fork default set increases list overlap and possible breakage. The [upstream list guide](https://github.com/gorhill/uBlock/wiki/Dashboard:-Filter-lists) says extra lists raise breakage risk and recommends keeping optimized uBlock lists. A deliberate core-plus-two-Helium-list selection is the practical compatibility choice; test Helium's actual dashboard before claiming the deployed set is active.

uBO discards duplicate filters, but additional lists still add update and compatibility surface. Auto-update uses each list's expiration metadata and updates in the background. At launch uBO normally loads cached lists rather than downloading all lists, according to the maintainer's [reference answer](https://github.com/gorhill/uBlock/wiki/Reference-answers-to-various-topics-seen-in-the-wild). Forcing cache bypasses or disabling cosmetic filtering to chase theoretical speed would discard useful behavior without evidence of a local performance problem. [Filter-list guide](https://github.com/gorhill/uBlock/wiki/Dashboard:-Filter-lists).

### Installation and Helium assets

Mozilla's [ExtensionSettings policy](https://mozilla.github.io/policy-templates/#extensionsettings) says `allowed` permits user installation but does not install an extension. `normal_installed` installs it and permits disabling; `force_installed` installs it and prevents disabling. An extension's `3rdparty.Extensions.<id>` settings can matter only when that extension is installed and running; this last sentence is an inference from the policy roles. The shared Gecko extension definition now uses `normal_installed` for uBO in Firefox, Zen, and the Zen Shopping profile, including an AMO `install_url` through the [extension policy builder](../../modules/home/browsers/shared/extension-policies.nix). This keeps protection present while permitting a user to disable the extension temporarily for diagnosis. Other optional daily extensions remain `allowed`.

Helium's [current dependency declaration](https://github.com/imputnet/helium/blob/main/deps.ini) fetches its uBO fork for the browser build. Its [service integration patch](https://github.com/imputnet/helium/blob/main/patches/helium/core/ublock-helium-services.patch) injects `adminSettings.assetsBootstrapLocation` with the resolved `/ubo/assets.json` service URL when Helium services and uBO assets are enabled. It also changes the managed-storage read path: if `adminSettings` is not an object, Helium replaces it with an empty object before injecting that location. The [fork's restore code](https://github.com/imputnet/uBlock/blob/main/src/js/storage.js) accepts a JSON string or an object, but Helium's earlier conversion means a Chromium policy JSON **string** can be lost. This is a source-level inference requiring runtime verification. Avoid relying on a Nix `adminSettings` string for clearing old dynamic rules or forcing a bootstrap URL until the installed Helium build's behavior is checked.

The service URL returned HTTP 406 to an unauthenticated `curl -I` request on 2026-10-01. That response alone does not establish whether Helium can fetch it: the browser may send different headers or have service-specific access. The built-in service preference and user consent determine the intended URL; hard-coding it in a separate policy is unnecessary according to the patch and could bypass those choices. Check the browser's uBO dashboard and filter-list update status in an activated profile.

The [uBO README](https://github.com/gorhill/uBlock/blob/master/README.md) advises against running another content blocker alongside uBO. Its [Firefox comparison](https://github.com/gorhill/uBlock/wiki/uBlock-Origin-works-best-on-Firefox) documents CNAME, HTML filtering, and first-request protections that Chromium cannot fully match. Helium's bundled fork should be judged by its installed version and observed filtering, without assuming Firefox parity.

## Validation and limits

This was a source and repository review on 2026-10-01. The two live `assets.json` files were parsed to compare enabled keys; the Helium service integration and uBO restore paths were read. No browser was launched, no Nix evaluation or system build ran for this research note, and the service endpoint was not validated from inside Helium. Source-level claims about the installed build, managed-storage injection, and filter updates require browser runtime checks.

## Implication for this repository

Keep the core list selection and only the two Helium-specific lists where applicable. Configure privacy controls through supported string pairs, keep Gecko's startup suspension and the full user interface, and avoid per-site rules and custom exceptions. The [shared extension definition](../../homes/shared/local/browsers/extensions.nix) now selects `normal_installed` for uBO across the Gecko profiles. Verify installation and effective uBO settings in each activated profile and the Helium policy in an activated browser, particularly the `adminSettings` type interaction and list update state. See the current [Gecko policy builder](../../modules/home/browsers/shared/ublock-policy.nix) and [Helium policy](../../modules/shared/chromium-policies.nix).
