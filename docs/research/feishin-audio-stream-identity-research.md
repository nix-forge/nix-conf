# Feishin's audio stream name in Noctalia

Reviewed: 2026-09-28. Scope: pinned Noctalia revision `273439338a50c51bdef105ba243175d7a914965a`, Feishin 1.17.0, and mpv 0.41.0 on Linux.

## Answer

Set `--audio-client-name=Feishin` only for the mpv process Feishin launches. mpv uses this setting for the PipeWire stream's application and node identity. Noctalia also needs to prefer an exact `application.id` desktop match over the renderer executable. At the pinned revision, it checks `application.process.binary` first, so an otherwise correctly named Feishin stream is still labeled "mpv Media Player". The current stream reports `mpv` in both fields.

The clean configuration point is Feishin's dedicated mpv executable. Make that executable a small Nix-built wrapper around unwrapped mpv that adds `--audio-client-name=Feishin` and forwards all arguments. Link it at the app-specific path managed by the [Feishin mpv integration](feishin-mpv-nix-research.md). Standalone mpv keeps its normal name and Home Manager scripts. Feishin already passes `--no-config`, so putting the setting in the user's `mpv.conf` would not provide this behavior.

## Findings and sources

- [Noctalia's pinned PipeWire reader](https://github.com/noctalia-dev/noctalia/blob/273439338a50c51bdef105ba243175d7a914965a/src/pipewire/pipewire_service.cpp#L1065-L1110) records `application.name`, `application.id`, `application.process.binary`, `node.name`, `node.description`, and stream title from each node. Its [Application Volumes name resolver](https://github.com/noctalia-dev/noctalia/blob/273439338a50c51bdef105ba243175d7a914965a/src/shell/control_center/tabs/audio_tab.cpp#L505-L565) starts with the application name, applies fallbacks, and may replace the result with a matched desktop entry's name. [Desktop matching](https://github.com/noctalia-dev/noctalia/blob/273439338a50c51bdef105ba243175d7a914965a/src/shell/control_center/tabs/audio_tab.cpp#L447-L485) checks the executable before the application ID. The [PipeWire property reference](https://docs.pipewire.org/group__pw__keys.html) defines these keys.
- [mpv 0.41.0's audio options](https://github.com/mpv-player/mpv/blob/v0.41.0/audio/out/ao.c#L144-L189) default `audio-client-name` to `mpv`. Its [PipeWire output](https://github.com/mpv-player/mpv/blob/v0.41.0/audio/out/ao_pipewire.c#L574-L586) assigns the configured client name to `node.name`, `node.description`, `application.name`, `application.id`, and `application.icon-name`. The [mpv manual](https://mpv.io/manual/stable/#audio) describes `--audio-client-name` as the name reported to the audio API.
- [Feishin 1.17.0's player](https://github.com/jeffvli/feishin/blob/v1.17.0/src/main/features/core/player/index.ts#L104-L180) invokes mpv with `--no-config` and accepts extra parameters. Its [renderer engine](https://github.com/jeffvli/feishin/blob/v1.17.0/src/renderer/features/player/audio-player/engine/mpv-player-engine.tsx#L68-L70) passes `mpvExtraParameters` from the renderer settings to mpv at initialization. The [Playback settings form](https://github.com/jeffvli/feishin/blob/v1.17.0/src/renderer/features/settings/components/playback/mpv-settings.tsx#L145-L182) exposes those parameters to the user. That is a supported app-level alternative, but the setting lives in the renderer's local storage and would require managing or asking the user to change that preference. A dedicated executable keeps the system identity with the executable that creates the stream.

## Validation and limits

On the current Linux session, `pw-dump` showed Feishin's mpv playback node with `application.name=mpv`, `application.id=mpv`, `node.name=mpv`, and `node.description=mpv`. The installed mpv desktop entry names itself "mpv Media Player"; the installed Feishin entry names itself "Feishin". A local silent-audio probe using `--audio-client-name=Feishin` changed the PipeWire node's application name and ID to `Feishin`, but its client still reported `application.process.binary=mpv`. This confirms that mpv's flag alone cannot overcome Noctalia's current lookup order. With the patched Noctalia package temporarily running, that probe appeared as "Feishin" with its desktop icon. An existing playback stream without the new mpv setting still appeared as "mpv Media Player" in the same panel. The normal Noctalia service was restored after the check. mpv may select a different audio output in another environment; the PipeWire-specific property assignment applies when its PipeWire output is active.

## Implication for this repository

The dedicated Feishin mpv wrapper now adds `--audio-client-name=Feishin`. The pinned Noctalia package checks an exact `application.id` desktop entry before looking up the renderer binary, while retaining the old fallback for unknown IDs. The package built and its UI showed the expected name and icon with a test stream. The running Feishin playback process and normal Noctalia service have not been switched to the new configuration. Do not add the mpv option to `programs.mpv.config`, which governs standalone mpv and is bypassed by Feishin's `--no-config` startup.
