# Moonfin navigation artwork and trailer quality

Reviewed: 2026-10-03. Scope: Moonfin Core 2.6.0, `b86bbe6021eff5befdf311134bf3e831c032f21f`, native Linux, macOS and Apple TV; upstream main inspected through `8c75a0dfdfc3cb89093bc32fc2c440dbd0a21821`.

## Answer

There is no universal 4K artwork preference in the inspected release. Several screens explicitly request images much smaller than 4K, including episode stills that omit display pixel density. Trailers use different routes on macOS and Linux/Apple TV. A post-release upstream change targets better YouTube trailers, described by its author as up to 1080p. The latest published release remains 2.6.0; updating to another stable release cannot yet supply that fix.

## Findings and sources

- [Episode card source](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/screens/detail/item_detail_screen.dart#L14533-L14562) requests a primary still with maxHeight 250 on compact layouts, otherwise 250 times desktop UI scale. Other episode card variants request [240](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/screens/detail/item_detail_screen.dart#L14777-L14802) and [220](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/screens/detail/item_detail_screen.dart#L15020-L15045). These paths omit device pixel ratio. Their series-thumbnail substitutes derive a 16:9 width from the same height. These are source observations and a plausible cause of softness on dense displays, not a visual diagnosis of a particular library.
- [Minimalist episode detail](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/screens/detail/minimalist/minimalist_detail_content.dart#L286-L311) differs: its still width is 240 to 440 logical pixels and the request doubles that width. Layout choice therefore matters. [Media-bar requests](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/data/repositories/media_bar_repository.dart#L520-L533) and [backdrop decoding](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/widgets/media_bar.dart#L62-L76) both cap width at 1280. The [Nouveau episode rail](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/screens/detail/nouveau/episodes/nouveau_episodes_section.dart#L1113-L1118) requests stills at a fixed maximum height of 360.
- Shared [artwork request sizing](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/util/artwork_request_size.dart) caps DPR at 2 and rounds requests into coarse buckets. [ArtworkDecode](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/widgets/image_source.dart#L60-L115) rounds decode widths upward by 20, with default maxSourceWidth 1920. [MediaCard](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/widgets/media_card.dart#L43-L50) caps landscape decodes 960 and portrait 640. These are individual path bounds, not a claim that every app image uses the same limit.
- [Jellyfin image API](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/packages/server_jellyfin/lib/src/api/jellyfin_image_api.dart#L8-L44) requests compression quality 90 on primary/backdrop/thumb images. Raising compression quality alone cannot restore missing pixels. No general image-quality preference appeared in the inspected preference source. [Performance Mode UI](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/screens/settings/panel/advanced_options_screen.dart#L56-L75) is Android-only, with Auto/Standard/Reduced choices.
- [Issue #875](https://github.com/Moonfin-Client/Moonfin-Core/issues/875) is closed as not planned. Its July report of a 0.9 decode multiplier describes older code. The [September 19 artwork change](https://github.com/Moonfin-Client/Moonfin-Core/commit/81ec0182040b7a28c60af334145b0252131cc31d), already included in 2.6.0, moved to sizing by painted dimensions. Do not apply the old formula to current Home cards.
- The [pinned YouTube resolver](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/data/services/youtube_stream_resolver.dart#L331-L433) first accepts HLS/DASH manifests. Its file fallback favors audio-bearing MP4/H264 and scores resolution closest to 480p; the score clamps quality to 1080. It does not assemble separate adaptive video/audio streams. Thus merely increasing a cap cannot guarantee 4K.
- [Embedded YouTube selection](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/widgets/media_bar.dart#L1705-L1714) includes macOS, iOS, Android and web; Linux and Apple TV use the direct resolver. The [native embedded stage](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/widgets/web_youtube_trailer_io.dart#L58-L62) is 1920x1080, though YouTube controls actual adaptive quality.
- [Upstream trailer commit 3c29f48](https://github.com/Moonfin-Client/Moonfin-Core/commit/3c29f487fb771b07f79878ecc194cf5b6c71a4b4), September 26, changes to a Vision Pro manifest-first route, Android muxed fallback, visitor-id retry and original soundtrack selection. Its title explicitly says up to 1080p. This is unreleased relative to the [latest 2.6.0 release](https://github.com/Moonfin-Client/Moonfin-Core/releases/tag/2.6.0), published September 24. A backport requires coordinated caller changes, not just replacing one constant.
- [Local trailer selection](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/widgets/media_bar.dart#L1042-L1107) precedes remote YouTube trailers. It negotiates PlaybackInfo with direct play enabled and [uses the actual backend device profile](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/widgets/media_bar.dart#L1829-L1837). Supplying a compatible high-quality local trailer can therefore avoid the low-quality YouTube fallback across clients, subject to source quality, available codecs and server negotiation.
- Settings > Personalization > Details Screen exposes [Open trailers externally](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/ui/screens/settings/panel/details_screen_settings_screen.dart#L154-L160). The [launch helper](https://github.com/Moonfin-Client/Moonfin-Core/blob/b86bbe6021eff5befdf311134bf3e831c032f21f/lib/util/detail_trailer.dart) sends remote trailers to an external app or browser. This bypasses the built-in resolver for manually opened trailers; it does not improve inline previews or guarantee a particular resolution. Availability depends on a suitable handler, and Kids Mode disables it.
- Jellyfin supports [local trailers](https://jellyfin.org/docs/general/server/media/movies/) and [episode artwork files](https://jellyfin.org/docs/general/server/media/shows/). A compatible high-quality file in a movie's `trailers/` directory can supply a better source. Check one title and its negotiated playback before adding files throughout a library.

## Validation and limits

Read pinned source and current primary upstream source/history. No visual reproduction, network media-quality measurement, authenticated image-source inspection, build or playback test was performed. The local public Jellyfin endpoint reported version 12.1.0. Authenticated library inspection was unavailable, and the installed versions on Apple TV and macOS remain unverified. Full-resolution server artwork may itself be small; a larger request cannot reconstruct absent detail. A 4K movie does not imply a 4K metadata still or trailer. Existing client decode bounds still apply after replacing server artwork.

## Implication for this repository

Prefer supplying original high-resolution artwork and compatible local trailers when available, because those assets benefit all clients. Validate one affected title before bulk replacement or regeneration. Client-request/decode corrections must ship in the relevant app, including Apple TV and signed macOS builds; a Linux-only Nix patch cannot fix all devices. Recheck the upstream trailer change when adopting the next release, and propose a cross-platform artwork-quality option or density-correct episode sizing upstream. Do not promise 4K throughout navigation or silently switch all clients to an unreleased build.

The existing [Linux performance investigation](moonfin-linux-performance-research.md) records separate frame-pacing limits. Higher image resolution increases decoding and cache costs, so validate clarity and navigation responsiveness together. No application, package, server configuration or media asset was changed during this investigation.
