# Aurral patch audit: upstream context

## Current review, 2026-10-16

The current local package selects stable2.10.0 with seven patches. The historical analysis below covers2.9.1 with six. See the [current Aurral matrix](upstream-personal-packages-research.md#aurral-current-stable-package-and-seven-patches) for merged lossless-tagging PR1132, closed-unmerged1065, migration compatibility and the remaining contribution gates. Earlier test receipts retain their original scope.

Reviewed: 2026-10-06. Scope: six patches in `pkgs/pkgs/by-name/au/aurral/`, pinned to v2.9.1. Decision: which remaining problems warrant upstream pull requests.

## Answer

Do not port the six patches mechanically. Current upstream has overlapping merged work, sometimes built on different designs. Reproduce each residual problem at a fixed `main` commit and submit a small regression-tested fix. In particular, the 1,614-line local ListenBrainz Discover patch targets a fallback design that [PR #1045](https://github.com/lklynet/aurral/pull/1045) removed.

The pinned 2.9.1 package still uses all six patches to provide its documented behavior; this audit does not justify removing any of them from that build. Against current `main`, the two ListenBrainz patches and much of artist identity are already covered by different upstream work. Dedicated private audio tags and canonical artwork are product choices that need maintainer agreement before feature PRs. Lidarr enrichment needs a focused reproduction against the active scan path. Three smaller correctness bugs have the PRs below.

## Findings and sources

The [local recipe](../../pkgs/pkgs/by-name/au/aurral/package.nix) pins 2.9.1. Upstream [v2.10.0](https://github.com/lklynet/aurral/releases/tag/v2.10.0) was the latest stable release observed, published 2026-09-23. `main` was observed at [`81dbca7`](https://github.com/lklynet/aurral/commit/81dbca7fe476b390656167666c09594b41e2a44d) on 2026-10-06. New merged work is not necessarily in stable. The upstream [README](https://github.com/lklynet/aurral/blob/main/README.md) describes a Lidarr companion, while its [app overview](https://github.com/lklynet/aurral/blob/main/docs/src/content/docs/using/overview.mdx) describes a canonical index of Aurral and Lidarr files. [PR #1045](https://github.com/lklynet/aurral/pull/1045) states the maintainer wants one key-free Discover experience and a more standalone library/download path.

Upstream [CONTRIBUTING.md](https://github.com/lklynet/aurral/blob/main/CONTRIBUTING.md) asks for issue/PR search, a reproducible bug report if no issue exists, maintainer approval before feature implementation, one problem per PR, tests, and before/after screenshots for UI changes. It disfavors unrelated cleanup and new dependencies without need. The [PR template](https://github.com/lklynet/aurral/blob/main/.github/pull_request_template.md) calls for What changed, Why, scope, issue, UI evidence, checks not run, and release impact. Use a Conventional Commit title. The maintainer's [Lidarr add-flow issue #513](https://github.com/lklynet/aurral/issues/513) is precedent for narrowing a broad bug family and asking for a failing integration test before another patch. It is not the same as local scan enrichment.

Three bugs reproduced on `main` and have focused upstream fixes:

- [PR #1063](https://github.com/lklynet/aurral/pull/1063), linked to [issue #1062](https://github.com/lklynet/aurral/issues/1062), sends a play event's release-group MBID in ListenBrainz's `release_group_mbid` field. Previously Aurral sent it as `release_mbid`. The [ListenBrainz JSON specification](https://listenbrainz.readthedocs.io/en/latest/users/json.html) distinguishes the fields and asks clients to omit unknown values.
- [PR #1065](https://github.com/lklynet/aurral/pull/1065), linked to [issue #1064](https://github.com/lklynet/aurral/issues/1064), stops Aurral's download tagger from replacing a file's release MBID with a release-group MBID and carries a known release ID through the download job. The [Picard tag mapping](https://picard-docs.musicbrainz.org/en/v2.13/appendices/tag_mapping.html) confirms that `musicbrainz_albumid` is a release ID and `musicbrainz_releasegroupid` is a release-group ID.
- [PR #1067](https://github.com/lklynet/aurral/pull/1067), linked to [issue #1066](https://github.com/lklynet/aurral/issues/1066), transfers management settings when a name-keyed artist merges into its MBID-keyed record. It keeps an existing setting on the canonical record.

## Validation and limits

Read upstream repository metadata, contribution files, issues, and PR bodies through GitHub on 2026-10-06. A checkout of `81dbca7` was used for three bug reproductions. The ListenBrainz request test, generated-FLAC tag test, and artist-management merge test failed before their fixes and passed afterward with Node 26.10.0. The adjacent ListenBrainz rate-limit and yt-dlp metadata tests passed. Backend lint passed for all three PRs. The broader artist-MBID override test could not start locally because Honker's npm binary could not load `libsqlite3.so.0`; its application assertions were not reached. No live ListenBrainz submission or download was performed. Other patch themes were audited from source and discussions but have not been reproduced against this revision. Closed [PR #1056](https://github.com/lklynet/aurral/pull/1056) was superseded by closed [PR #1059](https://github.com/lklynet/aurral/pull/1059); neither merged, and neither establishes a local patch need.

## Implication for this repository

Keep local patches until the packaged version passes its focused regressions without them. Against current upstream `main`, test exact-path Lidarr enrichment, release-ID tagging, token-owner validation and redaction, native tag display/audio preservation, and release-group cover selection. Retire each local patch only after packaging a release with equivalent verified behavior.
