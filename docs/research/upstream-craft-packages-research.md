# Craft upstream contribution roadmap

Reviewed: 2026-10-16. Scope: 15 Craft recipe directories and 47 current patch files. This is source/review research with no new native builds. See the [decision roadmap](upstream-contribution-roadmap-research.md).

## Decision

Do not start another blanket ArtCraft PR round. All currently identified portable application fixes already have an owning proposal or accepted implementation. The most valuable work is completing existing reviews, preserving external authorship and reducing mixed patches by component after release adoption. Two **new Nixpkgs packages**, FigCraft and Craft Launcher, are legitimate contribution candidates; exact-name title searches found no matching proposal. This is a bounded negative search, not proof that no differently titled or unindexed effort exists.

There are **15 personal outputs and 47 patch files**: 14 applications including Launcher plus shared craft-fonts. Their current primary retirement paths are **9 merged/release-blocked files, 16 existing-open-proposal files, 10 distribution-policy files, 10 mixed files, and 2 compiler/dependency workarounds**. Counts are mutually exclusive by file; merged components inside mixed files are additional. Compared with prior local notes, PhotoCraft #5399 is now merged, moving one file from open to accepted. Zero immediate patch deletions follow: all 14 latest advertised stable tags peel to the exact currently selected source commits; craft-fonts has no advertised release and its main still equals the selected snapshot. Accepted repairs are newer than those selected stable sources.

Fresh evidence also corrects older Nixpkgs notes: WordCraft and SoundCraft initialization PRs are merged, followed by 0.6.1 updates. Both recipes are still absent at selected Nixpkgs `7fd4004d0511991fff3a0524856a9be09e28c5f0` (raw paths return404; merge-to-pin ancestry reports the pin behind). Current master `4c1af6a978eb8b64efec8ec5e8b3252f0057cf63` has 0.6.1 in the [WordCraft recipe](https://github.com/NixOS/nixpkgs/blob/4c1af6a978eb8b64efec8ec5e8b3252f0057cf63/pkgs/by-name/wo/wordcraft/package.nix) and [SoundCraft recipe](https://github.com/NixOS/nixpkgs/blob/4c1af6a978eb8b64efec8ec5e8b3252f0057cf63/pkgs/by-name/so/soundcraft/package.nix), while personal packages select0.7.0. Neither merge makes the personal implementation redundant.

## Priority backlog and actual blockers

1. **Existing proposal maintenance, before new proposals.** DesignCraft #987, EffectCraft #1591/#1592, PdfCraft #2399/#2622 and Launcher #314 report conflicting branches at this snapshot. Preserve upstream progress records and test assertions when rebasing; full-application CI gaps remain explicit. Mergeability is a moving GitHub computation, not a code review conclusion. No fresh rebase was performed here.
2. **Finish contributor-to-contributor handoffs already published in the existing proposals.** Launcher [#314](https://github.com/storytold/craft-launcher/pull/314#issuecomment-6224516715) has an authorship-preserving resolution on the contributor's fork, with original author instructions to fast-forward. Launcher [#328](https://github.com/storytold/craft-launcher/pull/328#issuecomment-6225987046) has a reviewed follow-up preserving customized desktop entries and ten focused tests. Do not create competing PRs or claim these are already in the proposal heads. The authors/maintainers must adopt them. The #314 head still conflicts; #328's current head still precedes its offered follow-up.
3. **Respect design decisions and review objections.** FigCraft [#582](https://github.com/storytold/figcraft/pull/582#issuecomment-6199517141) is held for the owner to decide whether the text crate may run `fc-list` and directly depend on rustix. The [published conflict resolution](https://github.com/storytold/figcraft/pull/582#issuecomment-6227577010) is now in the proposal head; the owner policy hold remains. Launcher [#355](https://github.com/storytold/craft-launcher/pull/355#pullrequestreview-5547513644) has a live correctness objection: discarding Exec during ownership comparison can overwrite a quoted custom wrapper. Its existing passing harness does not cover that edge case. Do not treat it as equivalent safe refresh.
4. **Unblock existing Nixpkgs packaging.** [craft-fonts #572622](https://github.com/NixOS/nixpkgs/pull/572622) has current approval and remains open; it blocks several app proposals. Review asset licensing, standard installFonts placement plus the build-input layout, then complete review on the existing PR. PhotoCraft's author explicitly paused further updates pending fonts. VectorCraft has both a dependency blocker and a reported wrong Cargo hash. GridCraft needs native Darwin bundle integration; existing application recipes also have concrete D-Bus/portal concerns. Contribute narrow fixes to those branches or coordinate with their owners rather than duplicate the package set.
5. **Prepare new FigCraft and Launcher Nixpkgs recipes only after checking naming/ownership again.** Separate source packaging and target-platform support from branding policy; expose install checks and truthful platform metadata. A personal package disappearing requires actual upstream recipe equivalence, not merely a merged init PR. Minimal Nixpkgs submissions should avoid shipping this whole research/test harness or imposing all local font policies.
6. **Improve already-merged WordCraft/SoundCraft recipes.** Update 0.6.1→0.7.0 as separate version PRs if no newer proposal appears. Separately add portable optional-font input/notice handling, signed native Darwin bundle integration and focused test restoration. Current WordCraft recipe has Linux-only asset/fixup installation and no Applications bundle; current SoundCraft recipe disables all tests, unconditionally depends on Linux libraries and runs patchelf. Broad rustc platform metadata does not prove Darwin support. Preserve test coverage rather than copy `doCheck=false` into the personal packages.
7. **Correct owning dependency, not application code.** Follow Candle Metal bounds proposals and Nixpkgs' coordinated LLVM22 default migration. GCC/libgomp needs a properly scoped human-reviewed GCC report/submission; there is no ArtCraft GitHub PR that can resolve the compiler root cause.

No maintainer milestone or release date establishes a reliable retirement date. Each retirement chain is accepted change → containing source/release → Nixpkgs dependency/recipe adoption if relevant → local pin selection → unpatched regression/native acceptance. Most current Craft patches are blocked at the first two steps.
