# Feishin mpv integration with Nix

> Historical snapshot: personal package recipes referenced here have since been retired or renamed. These audit findings describe the cited source, not the current package selection.

Reviewed: 2026-09-28. Scope: Feishin 1.17.0, pinned Home Manager and Nixpkgs revisions.

## Answer

Declare an app-specific Home Manager symlink to unwrapped mpv beside Feishin's settings, then set `mpv_path` to that stable sidecar path. This uses Home Manager's file lifecycle to update the link with each home generation. It avoids a profile alias, a Nix store path in Feishin's mutable settings, and dependence on the environment inherited by Electron. It also works when a macOS Homebrew mpv is installed. Keep Feishin's separate MPRIS player and the regular script-enabled mpv command for standalone use.

## Findings and sources

- [Feishin's player code at v1.17.0](https://github.com/jeffvli/feishin/blob/v1.17.0/src/main/features/core/player/index.ts#L95-L180) reads `mpv_path` from its settings store and passes it as the binary path to `node-mpv`. An absent path becomes `undefined`, leaving `node-mpv` to resolve `mpv` from the process environment. The same code passes `--no-config` and `--load-scripts=no` as mpv arguments.
- The [Nixpkgs Feishin package](https://github.com/NixOS/nixpkgs/blob/44a91898084f46797b5fac650c7e8c9ac38c43d4/pkgs/by-name/fe/feishin/package.nix#L85-L110) already creates `bin/feishin` wrappers on both platforms with `--prefix PATH : "${lib.makeBinPath [ mpv-unwrapped ]}"`. Its Linux desktop item starts `feishin %u`, so the wrapper is used for desktop launches. The same package builds a macOS `.app`, but [Home Manager's `copyApps` implementation](https://github.com/nix-community/home-manager/blob/4ac5a2ae9025eab1ebece4f9df8c315fd84a738a/modules/targets/darwin/copyapps.nix#L101-L143) copies the bundle to `~/Applications` for LaunchServices; that launch does not run the `bin/feishin` wrapper. The bypass follows from these source paths and the app launch route.
- [Feishin's macOS binary resolution](https://github.com/jeffvli/feishin/blob/v1.17.0/src/main/features/core/player/index.ts#L95-L149) checks `/opt/homebrew/bin/mpv` and `/usr/local/bin/mpv` before falling back to `mpv` from `PATH`. Therefore adding the Nix mpv directory to the copied app's `PATH` alone does not select it reliably when Homebrew mpv exists. An explicit app-specific `mpv_path` wins before those candidates.
- Feishin pins a [Node-MPV fork at revision `32b4d643`](https://github.com/jeffvli/feishin/blob/v1.17.0/pnpm-lock.yaml#L4631). Its [`start()` implementation](https://github.com/jeffvli/Node-MPV/blob/32b4d64395289ad710c41d481d2707a7acfc228f/lib/mpv/_startStop.js#L73-L89) spawns `mpv` with inherited environment when no binary is configured. Its [`checkMpvBinary`](https://github.com/jeffvli/Node-MPV/blob/32b4d64395289ad710c41d481d2707a7acfc228f/lib/util.js#L101-L122) calls `fs.stat()` for any truthy binary value. Thus setting `mpv_path` to the bare string `mpv` is not equivalent to leaving it unset and can fail before spawn.
- [Feishin's Linux MPRIS module at v1.17.0](https://github.com/jeffvli/feishin/blob/v1.17.0/src/main/features/linux/mpris.ts#L1-L18) publishes a player with identity `Feishin`.
- The pinned [Home Manager mpv module](https://github.com/nix-community/home-manager/blob/4ac5a2ae9025eab1ebece4f9df8c315fd84a738a/modules/programs/mpv.nix#L61-L68) creates `programs.mpv.finalPackage` by overriding `pkgs.mpv` with the configured scripts, and installs that final package in `home.packages`. The [pinned Nixpkgs mpv wrapper](https://github.com/NixOS/nixpkgs/blob/44a91898084f46797b5fac650c7e8c9ac38c43d4/pkgs/by-name/mp/mpv/package.nix#L70-L108) explicitly adds each script as a `--script=...` argument. Therefore Feishin's `--no-config` and `--load-scripts=no` do not remove these wrapper supplied arguments; this is an inference from their independent command line effects. The [mpv manual](https://mpv.io/manual/stable/#options) documents `--load-scripts` as controlling automatic loading from the configuration subdirectory and `--script` as explicitly loading a script.
- Pinned [Home Manager `home.file`](https://github.com/nix-community/home-manager/blob/4ac5a2ae9025eab1ebece4f9df8c315fd84a738a/modules/files.nix#L64-L68) links declared files into the user's home, with the generation as source; `xdg.configFile` provides the XDG config variant. The local [mpv module](../../modules/home/mpv/default.nix) includes `pkgs.mpvScripts.mpris` on Linux. The local [Feishin module](../../modules/home/feishin.nix) provisions the executable path in Feishin's mutable settings at activation.

### Alternatives considered

The Nixpkgs `bin/feishin` wrapper's `PATH` is sufficient for a Linux launch with `mpv_path` unset, but macOS LaunchServices bypasses that wrapper, and Feishin's Homebrew candidates precede `PATH`. A package-level source or asar patch could set a Nix-built absolute mpv fallback inside Feishin; that path would be a legitimate package dependency and update with each derivation. It would, however, tie this local integration to Feishin's internal player code and add maintenance to the existing [package overlay](https://github.com/nix-forge/nixpkgs-personal/blob/d199632c9727bd2ed2ff8782c2ac7fcd69d27254/pkgs/by-name/fe/feishin-managed/package.nix). A symlink under Home Manager's general profile would work technically, but the sidecar belongs to Feishin and avoids exposing another command in the user's general `bin` directory.

## Validation and limits

Inspected Feishin's tagged source, its pinned Node-MPV fork, the pinned Home Manager and Nixpkgs sources in the local Nix store, and the current configuration. On the current Linux host, the installed profile `bin/mpv` resolves to `mpv-with-scripts`. `strings` on that installed wrapper showed an explicit `--script=` argument for `mpv-mpris` alongside the other mpv scripts. Linux and Darwin module evaluations select their respective app-specific sidecar paths and unwrapped mpv binaries. A live Linux session used the sidecar to launch mpv without script arguments and exposed only Feishin's MPRIS player. Full Home Manager activation of the new link and Darwin playback remain untested.

## Implication for this repository

Use Home Manager's `xdg.configFile` on Linux and `home.file` on Darwin to link an app-specific path in Feishin's settings directory to `lib.getExe config.programs.mpv.finalPackage.unwrapped`. Provision that sidecar path as Feishin's `mpv_path` at activation. Keep the regular Home Manager mpv package and its scripts for standalone playback. This avoids both a profile alias and a package source patch.
