# Tmux configuration research

## Recommendation

Use Home Manager's native `programs.tmux` options wherever they exist, then use
a small, typed local `programs.tmux.declarative` option set for tmux settings
that Home Manager does not expose. The module renders that typed data into the
generated XDG configuration; there is no maintained `tmux.conf` source file.
This preserves the useful custom UI and bindings without reverting to an
unstructured configuration blob. The generated file is immutable, so a manual
reload binding is misleading; apply a Home Manager generation, then start a
fresh server when testing configuration changes.

The module intentionally exposes a focused set of structured options, not a
Nix option for every tmux command. It covers the daily interactive behaviour:
`enable`, `package`, `terminal`, `shell`, `baseIndex`, `clock24`, `keyMode`,
`customPaneNavigationAndResize`, `resizeAmount`, `prefix` or `shortcut`,
`reverseSplit`, `mouse`, `focusEvents`, `aggressiveResize`, `escapeTime`,
`historyLimit`, `secureSocket`, `sensibleOnTop`, `plugins`, and `tmuxp`.
[Home Manager's tmux module](https://github.com/nix-community/home-manager/blob/03f4cd46bc1dd4f3a96da778d2ce9f7ce39dd450/modules/programs/tmux.nix)
is the authoritative list and shows the generated tmux commands.

Use this baseline for the options Home Manager models natively:

```nix
programs.tmux = {
  enable = true;
  terminal = "tmux-256color";
  keyMode = "vi";
  customPaneNavigationAndResize = true;
  resizeAmount = 10;
  mouse = true;
  focusEvents = true;
  historyLimit = 50000;
  escapeTime = 10;
  baseIndex = 1;
  clock24 = true;
  secureSocket = pkgs.stdenv.hostPlatform.isLinux;
};
```

This retains the useful behaviour in the existing setup without a hand-written
configuration file. It deliberately leaves `shell` unset, so tmux uses the
login shell selected by the session. Set it only if the configured shell path
is meant to override every host's login-shell policy.

## Rationale

| Goal | Decision | Reason |
| --- | --- | --- |
| Compatibility | Keep `terminal = "tmux-256color"` locally; validate remote hosts before exporting it over SSH. | tmux requires `TERM` to be `screen`, `tmux`, or a derivative. A remote host without the `tmux-256color` terminfo entry needs its terminfo installed or a more widely available fallback such as `screen-256color`. [tmux manual](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L4375-L4387) |
| Keyboard UX | Use vi copy/navigation mode, built-in `hjkl` navigation, repeatable `HJKL` resize bindings, a 10-cell resize step, and focus events. | These are directly generated by the module. Focus events are requested only when the outer terminal supports them and passed to programs in panes. [Home Manager implementation](https://github.com/nix-community/home-manager/blob/03f4cd46bc1dd4f3a96da778d2ce9f7ce39dd450/modules/programs/tmux.nix#L68-L97), [tmux manual](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L4457-L4465) |
| Responsiveness | Retain `escapeTime = 10`, rather than setting it to zero. | tmux waits after Escape to distinguish a literal Escape from Meta and function-key sequences. Ten milliseconds keeps interactive latency low without making those sequences unreliable. [tmux manual](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L4388-L4392) |
| Resource use | Bound scrollback at 50,000 lines per pane; keep `aggressiveResize = false` and use the built-in status line. | History is held per pane and the configured value is the maximum line count. Avoiding a shell-polled status line and third-party status plugins prevents periodic subprocess work; tmux's native status refresh defaults to 15 seconds. [tmux manual](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L4807-L4808), [status interval](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L5035-L5040) |
| Security | Keep Linux `secureSocket` enabled; keep it disabled on Darwin; do not enable passthrough. | Home Manager puts the Linux socket under the user runtime directory rather than `/tmp`; that is more secure but it does not survive logout. `allow-passthrough on` lets a program in a visible pane bypass tmux using escape sequences, so its secure default is off. [Home Manager option](https://github.com/nix-community/home-manager/blob/03f4cd46bc1dd4f3a96da778d2ce9f7ce39dd450/modules/programs/tmux.nix#L284-L291), [tmux passthrough](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L5691-L5702) |
| Terminal features | Declare `RGB`, clipboard, focus, title, and hyperlinks only for `xterm-ghostty` and nested `tmux-256color`. | Ghostty declares `xterm-ghostty` as its terminal type and supports the corresponding control sequences. The SSH fallback remains `xterm-256color` without feature overrides because remote terminfo and capabilities cannot be assumed. [Ghostty configuration reference](https://ghostty.org/docs/config/reference), [Ghostty terminfo](https://github.com/ghostty-org/ghostty/blob/main/src/terminfo/ghostty.zig), [tmux manual](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L4551-L4574) |
| Clipboard | Use tmux's `external` clipboard policy. | tmux may forward a user-initiated copy to Ghostty through OSC 52, but a program running in a pane cannot set the clipboard by emitting OSC 52 itself. [tmux Clipboard wiki](https://github.com/tmux/tmux/wiki/Clipboard) |

## Intentional omissions

The raw `tmux.conf` and reload binding are intentionally removed. Settings not
represented by Home Manager are declared once as typed Nix values and rendered
by the module: the native status UI, working-directory split and window
bindings, vi copy-mode keys, title policy, strict terminal features, clipboard
policy, and passthrough policy. Stylix's generated theme source remains ahead
of these settings, so theme colors are not duplicated or pinned to an obsolete
palette.
document that built-in feature set.

Likewise, leave `sensibleOnTop` and third-party plugins disabled. The sensible
plugin is itself injected with `run-shell`, while Home Manager appends all
selected plugins to the generated configuration. A small, option-only base is
faster to start, easier to audit, and has less plugin supply-chain exposure.
Add a Nix-packaged plugin later only for a concrete workflow that the built-in
UI cannot handle.

Do not add `lock-after-time` until there is a tested, host-specific
`lock-command` for both the NixOS graphical session and Darwin. tmux supports
idle locking, but its lock command is an OS integration boundary, not a safe
cross-platform default. [tmux lock option](https://github.com/tmux/tmux/blob/3.7c/tmux.1#L4828-L4840)

## Verification

After applying the new generation, load it into an isolated tmux server rather
than changing the user's running server:

```sh
verify_socket="hm-tmux-verify-$$"
trap 'tmux -L "$verify_socket" kill-server 2>/dev/null || true' EXIT
tmux -L "$verify_socket" -f "${XDG_CONFIG_HOME:-$HOME/.config}/tmux/tmux.conf" \
  new-session -d -s verify
tmux -L "$verify_socket" show-options -g | rg 'default-terminal|history-limit|mouse|focus-events'
tmux -L "$verify_socket" show-options -s | rg 'escape-time'
```

Test locally and over SSH: true colour, Unicode, Meta and modified keys, mouse
selection, focus-sensitive editors, copy mode, nested tmux, detach/reattach,
and a fresh login on Linux to confirm the secure runtime socket lifecycle.
