## What current upstream source establishes

The development switch handler still drops `CloseSwitch` when closed, opens later without checking modifier state, and requeues repeated `OpenSwitch` navigation as a separate message. Its GTK controller only connects key presses. The release bindings still lack `IgnoreMods`, and the vendored IPC library has no `key_is_down` helper. These are the relevant local-patch behaviors that have not landed. [Switch handler](https://github.com/H3rmt/hyprshell/blob/dce45069922d99bd702999de260f9ca19cdea957/crates/windows-lib/src/switch/root.rs#L187), [binding implementation](https://github.com/H3rmt/hyprshell/blob/dce45069922d99bd702999de260f9ca19cdea957/crates/exec-lib/src/binds.rs#L91), [IPC helpers](https://github.com/H3rmt/hyprshell/blob/dce45069922d99bd702999de260f9ca19cdea957/dep-crates/hyprland/src/ctl.rs).

The development branch renamed `dep-crates/hyprland-rs` to `dep-crates/hyprland` and added optional live thumbnails with their own timers and close cleanup. Port the behavior into that code, preserving thumbnail lifetime and feature combinations. [Development switch component](https://github.com/H3rmt/hyprshell/blob/dce45069922d99bd702999de260f9ca19cdea957/crates/windows-lib/src/switch/root.rs), [workspace manifest](https://github.com/H3rmt/hyprshell/blob/dce45069922d99bd702999de260f9ca19cdea957/Cargo.toml).

The existing local report records deterministic close-before-open failures, 200 timing cases, and passing patched desktop checks. Those are prior observations recorded in this configuration repository; this investigation did not rerun the live desktop tests. Use their scripts and traces as starting evidence and reproduce against an unpatched upstream build before claiming current upstream validation. Carry these constraints into the implementation prompt:

- Treat left/right modifier state as one compositor snapshot, as the revised local helper now does. Retain an overlap/handoff test to prevent regression to mixed-time results.
- Preserve bounded asynchronous work, limit concurrent requests, and reject stale results after close, cancellation, reload, or a new selection. The original local patch called the unbounded synchronous transport from GTK updates; the revised patch uses the asynchronous path and a timeout. [IPC transport](https://github.com/H3rmt/hyprshell/blob/dce45069922d99bd702999de260f9ca19cdea957/dep-crates/hyprland/src/instance.rs#L66).
- Preserve legacy configuration support. The existing bindings deliberately fall back to legacy syntax; unconditional `repl` polling needs a capability path and controlled failure behavior. The revised patch suppresses repeated errors but makes every commit depend on query success. Retain a valid release-event path for unsupported query capabilities. A state-query failure must not itself become an assumption that the modifier was released. [Binding fallback](https://github.com/H3rmt/hyprshell/blob/dce45069922d99bd702999de260f9ca19cdea957/crates/exec-lib/src/binds.rs#L63).
- Preserve Escape cancellation, both modifier sides, Shift reversal, and Tab-held release. Keep ordered navigation from being overtaken by a queued close. Stop reconciliation on closure and component destruction, including current thumbnail/config reload paths.
- Test delayed open, stale close while held, release during focus handoff, no release notification, both modifier sides held, direction changes, fast repeated chords, unsupported/malformed/stalled state queries, and late async results after Escape or reopening. Verify Alt, Ctrl, and Super and the supported Lua/legacy paths.
- Keep the PR focused on switch-mode correctness. CSS, monitor preferences, Nix packaging, version bumps, new switch configurations, and live-preview features are unrelated.

The `socat` command is hidden from normal CLI help, and the source describes `OpenSwitch` as coming from keybindings and `CloseSwitch` as coming from modifier release. No user-facing guarantee of an independent persistent scripted picker was found. Consequently, guarding these internal close messages by actual held state fits their documented source intent, but the PR should describe any changed scripted behavior and test explicit cancellation. Do not call that behavior a confirmed public API break.
